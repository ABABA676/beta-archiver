# Бета — ошибки и уроки

Каждая ошибка: **симптом → причина → фикс → урок.** Записи по датам.

## 2026-10-04

### 1. Сборка: `CS0117: "DockStyle" не содержит определение для "Fottom"`
- **Симптом:** `dotnet publish` падает, в `Select-Object -Last 60` видно только «упал (код 1)», самой ошибки нет.
- **Причина:** опечатка `DockStyle.Fottom` → `Fottom`.
- **Фикс:** исправить; искать ошибки через `dotnet build … | Select-String 'error'`, а не через `publish` с хвостом.
- **Урок:** первая сборка нового проекта — показывай **весь** вывод компилятора, иначе диагностика идёт вслепую.

### 2. `build.ps1` после правки → `ParserError` (кракозябры вместо русского текста)
- **Симптом:** PS 5.1 ругается на `Write-Host "==> …"`, ошибки выглядят как `���`.
- **Причина:** правка файла сняла **UTF-8 BOM**; PS 5.1 читает `.ps1` без BOM в ANSI (cp866) — кириллица ломает парсер.
- **Фикс:** вернуть BOM: `[IO.File]::WriteAllText($f, [IO.File]::ReadAllText($f, [Text.Encoding]::UTF8), (New-Object Text.UTF8Encoding $true))`.
- **Урок:** правило ваулта повторилось снова — **после любой правки `.ps1` с русским текстом проверять/возвращать BOM.** Для `.cs` и `.md` BOM не нужен, компилятор и Obsidian понимают UTF-8 без него.

### 3. Вывод программы не попадает в консоль (`& $exe --selftest *> $log` → 0 байт)
- **Симптом:** файл лога пустой, `$LASTEXITCODE` пустой, кажется, что программа не запускалась.
- **Причина:** приложение собрано как `WinExe` (GUI-подсистема); PowerShell не перенаправляет его вывод оператором `*>`, а `$LASTEXITCODE` не выставляется.
- **Фикс:** `Start-Process -FilePath $exe -ArgumentList '--selftest' -NoNewWindow -Wait -PassThru -RedirectStandardOutput $out -RedirectStandardError $err`, результат — в `$proc.ExitCode`, читать `Get-Content -Encoding UTF8`.
- **Урок:** у GUI-приложений вывод и код возврата берём **только** через `Start-Process … -Wait -PassThru`. Заодно это единственный способ получить честный код возврата (тот же приём, что в Tormentum `agent.py`).

### 4. 7-Zip отдаёт пути с обратными слэшами (`Path = Исходные данные\вложенная\файл.txt`)
- **Симптом:** «общий корень» не находится, `Split('/')` не делит.
- **Причина:** в `-slt` Windows-пути приходят с `\`.
- **Фикс:** в `Engine.List` путь нормализуется: `line[7..].Replace('\\', '/')`.
- **Урок:** любой вывод внешней программы нормализуй в одном месте (парсинг), а не у потребителей.

### 5. 7-Zip **не помечает** непустые папки (`Folder = +` только у пустых)
- **Симптом:** тест «в списке есть папка» падает, хотя папка в архиве есть.
- **Причина:** в формате 7z непустые папки не хранятся отдельными записями — они выводятся из путей файлов.
- **Фикс:** проверять структуру по общему префиксу путей (`list.Select(e => e.Path.Split('/')[0])`), а не по флажку.
- **Урок:** «упавший» тест не всегда означает баг — иногда неверно ожидание. Читай документацию формата, а не подгоняй тест.

### 6. Правка одного файла дважды в одном параллельном блоке потеряла метод `UiTest`
- **Симптом:** `error CS0103: Имя "UiTest" не существует`, хотя правка отчиталась «успешно».
- **Причина:** две правки одного файла в одном блоке читают старую версию; вторая запись затирает первую.
- **Фикс:** применять правки одного файла **последовательно**, либо одним `edit` с общим контекстом.
- **Урок:** делегировать субагентам — можно и нужно, но **разные файлы**. Правки одного файла всегда сам и по одной.

### 7. `InvalidVariableReferenceWithDrive` на `"-- $mode: код …"`
- **Симптом:** парсер PS спотыкается о `$mode:`.
- **Причина:** `$var:` — это синтаксис переменной с указанием диска.
- **Фикс:** писать `$mode — код …` или `${mode}: код …`.
- **Урок:** после `$имя` в строке ставь пробел, тире или `${}` — двоеточие не ставь.

### 8. Ложноположительная проверка «отмена отрабатывает (|| true)»
- **Симптом:** тест проходит всегда, ничего не проверяя.
- **Причина:** страховка `caught || true`, чтобы не ловить гонку быстрого 7z.
- **Фикс:** отменять токен **до старта** (`cts.Cancel()`) — тогда `OperationCanceledException` детерминирован, плюс отдельная проверка, что процессов `7z` не осталось.
- **Урок:** тест, который не может упасть, — это не тест. Если гонка мешает, переделай сценарий, а не ослабляй проверку.

### 9. `git` в ваулте записан как «отсутствует» — на самом деле есть
- **Симптом:** по памяти планировал обходиться без git.
- **Причина:** запись в `AGENTS.md` устарела.
- **Фикс:** `git` **2.55.0**, `C:\Program Files\Git\cmd\git.exe` — репозиторий создан, коммит сделан.
- **Урок:** проверять инструмент `Get-Command` перед тем, как считать его отсутствующим, и сразу править память.

### 10. Кириллица в имени сборки
- **Симптом:** ожидал проблем с `Бета.csproj` → `Бета.exe`.
- **Фикс:** ничего не делал — `dotnet publish` спокойно собрал `Бета.exe` (0,2 МБ).
- **Урок:** .NET SDK корректно работает с не-ASCII именами (в Git только отображает их октесками из-за `core.quotepath`). В пути на GitHub лучше ставить `git config core.quotepath false`.

### 11. Гонка правок повторилась: запись о проекте потерялась в `AGENTS.md`
- **Симптом:** две правки одного файла в одном параллельном блоке — обе «успех», в файле осталась только первая. Вторую (описание проекта «Бета») нашёл только через `grep` при подготовке отчёта.
- **Причина:** параллельные вызовы `edit` читают файл до записи; последний затирает предыдущий.
- **Фикс:** повторить вставку отдельным вызовом и **обязательно проверить `grep`**, что текст на месте.
- **Урок (второй раз за вечер):** **одна правка одного файла за раз.** Формула: `edit`/`write` одного и того же файла — строго последовательно; параллельно допустимо только для РАЗНЫХ файлов. Проверка результата обязательна, если правил файл, который важен для памяти.

### 12. `error CS7065` при `ApplicationIcon` — `.ico`, собранный вручную, битый
- **Симптом:** проект с `ApplicationIcon` не собирается: «Атрибут не распознан этой версией компилятора… ссылка на файл ресурса Win32 верна».
- **Причина (три, нашли разбором побайтово):** `ICONDIR` писался тремя `int` = **12 байт вместо 6**; в `ICONDIRENTRY` planes и bitCount тоже как `int`, запись кадра расползалась с 16 на 20 байт; `BITMAPINFOHEADER` получался **44 байта вместо 40**.
- **Фикс:** все трёхбайтовые поля писать как `[uint16]`; проверять результат разбором (смещения подряд, последний кадр ровно в конце файла, `40 + stride*h + маска == bytesInRes`).
- **Урок:** бинарный файл, который никто не читает, не считается рабочим. Сгенерировал — не значит работает. Нужен свой валидатор, как `pe_exports.ps1` для PE.

### 13. PowerShell: вызов функции в аргументах метода и регистр переменных
- **Симптом:** `::new(CA $a 255 214 160)` → «Отсутствует ")"»; `[SolidBrush]::new($Leaf)` → «не удалось преобразовать GraphicsPath в Color».
- **Причина:** в списке аргументов метода нельзя вызвать PS-функцию (это выражение, а не команда) — значение надо вычислить заранее. И **имена переменных в PowerShell не различают регистр**: локальный `$leaf` затирал скриптовый цвет `$Leaf`.
- **Фикс:** `$col = CA $a …` до вызова; локальные называть иначе (`$leafPath`, `$leafFill`).
- **Урок:** PS нестрог к именам, но строг к синтаксису. Плюс `$var: текст` → `InvalidVariableReferenceWithDrive` (уже было).

### 14. Регресс: сигнатуру 7z требовал от любого файла
- **Симптом:** после починки «Что внутри» сломалось чтение `.zip`/`.rar`/`.tar` — программа отвечала «это не архив».
- **Причина:** `LooksLikeArchive` считает архивом чужие форматы (7z их умеет), а проверка сигнатуры применялась ко всем.
- **Фикс:** сигнатуру 7z проверять **только** для `.b3ta`; для чужих форматов доверять 7-Zip. Добавлены 2 проверки-регрессии (`.zip`, `.gz`).
- **Урок:** после «улучшения» обязательно спросить, что сломалось. Тест на соседних случаях ловит это дешевле, чем жалоба.

### 15. `Cli.Pack`: `-mx` терялся из-за лишнего `Skip(1)`
- **Симптом:** `--pack -mx=9 арх файл` отрабатывал с кодом 0, но уровень оставался 5.
- **Причина:** `Cli` зовёт `Pack(args[1..])`, а внутри стоял ещё `a.Skip(1)` — первый аргумент молча отбрасывался.
- **Фикс:** разбирать `-mx=N` по всему списку; **проверка размером:** `-mx=0` (Copy) обязан дать архив БОЛЬШЕ исходника. Именно это и поймало баг — не код, а sizes.
- **Урок:** у флага с числовым значением проверяй **эффект**, а не «код возврата 0». Сжатие — идеальный случай: `-mx=0` больше, `-mx=9` меньше.

### 16. `preview.png` резал кадр 256
- **Симптом:** на контрольном листе яблоко на 256 обрезано справа и сверху.
- **Причина:** `$cell = 150` жёстко, а максимальный кадр 256.
- **Фикс:** `$cell = [Math]::Max(160, $sizes[-1] + 24)`. Плюс: `Bitmap.Dispose()` для кадров перенесён **в самый конец** — до него `DrawImage` падал с «недопустимый параметр», потому что контрольный лист рисует те же битмапы.
- **Урок:** визуальный артефакт надо открывать и смотреть; «скрипт отработал» ≠ «картинка правильная».

### 17. В реестре ProgID ≠ имя программы
- **Симптом:** в `OpenWithProgids` писалось `7-Zip`, а настоящий ProgID на машине — `7-Zip.7z` (проверено: `HKCR\7-Zip` не существует).
- **Последствие:** 7-Zip не появлялся в «Открыть с помощью» — обещание пользователю было ложным.
- **Фикс:** брать ProgID из реестра в момент привязки (`HKCR\<расширение>` → default), отсутствующие пропускать и честно сообщать в интерфейсе.
- **Урок:** имена в реестре задаёт не программа, а установщик. Не угадывать — спрашивать.
